The version requirements equal the versions the tags carry. `filament-contract-model` `version = "0.1.2"` with `tag = "v0.1.4"` is accurate: the lock records model 0.1.2 at the v0.1.4 commit, and the comment above it says the model crate lives in the IR repository.
- Cargo.lock (examined). A set diff of `(name, version, source)` against main lists only first-party packages, plus `chrono 0.4.45` removed (filament-verification-contracts v0.2.0 moved to `time`, which was already locked at 0.3.55). The only consumer is the serialized claim map (`src/oracle/equality/mod.rs:1125`), and generation delegates evaluation to the owner's `CheckedEquality`, so a Float schedule that reached generation would be recorded and executed by the owner, not mishandled. Mutant `Float => Ok(Self::Plan)` fails `tc_029_ac50_*` at the owner-selection assertion. The test is non-tautological: it gets the schedule from a real `TypeEnvironment::check_equality` over float64 and checks the reader refusal on a real package. The spec text of AC-50 misstates FSL, FND-006 (gap-analysis SR). The new `"ieee"` arm in `tests/composite_equality_support/package.rs:267` is unreachable, because `family_of` never returns `"ieee"`, FND-011.

## Verdict

The pin move itself is clean: every tag exists and matches the lock, the lock diff is first-party only plus the chrono removal, no first-party crate resolves twice, and emitted and scratch manifests take their sources from one const authority. The drift test, the Float mirror test and the Bytes/JsonObject descriptor test each kill a mutant. The code changes for Float, Bytes, JsonObject, frame_depth and LiveOccurrences are exhaustive and correct. The PR is not mergeable as pushed. It commits about 9.6k lines of local logs, carrying home-directory paths, to a public repository (FND-001, high). The FSL rev is no longer the head of #2841 (FND-002, high). The test suite has 42 new failures (FND-007, gap-analysis SR).
