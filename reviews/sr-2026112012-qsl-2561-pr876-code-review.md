## Summary

Ticket: QSL-2561 (re-pin contract-codegen to the current FSL release revision). The PR moves
`fsl-replay` and `fsl-package` from 374fe2a8 to 8f71444d, moves `filament-contract-ir` and
`filament-contract-model` (normal and dev) from 4c91eff6 to af45a983, and adds FSL's new
`ReplayRequestWire::certificate: Option<serde_json::Value>` member to codegen's two request
builders, two integration-test fixtures and the `same_wire` equality check.

What was checked:

- Pins. Every FSL line in Cargo.toml resolves to 8f71444d8ae0e786a943c71cb84f9268c07c1285, and
  all eight FSL lock entries (fsl-cst, fsl-eval, fsl-forms, fsl-foundation, fsl-package,
  fsl-replay, fsl-route, fsl-semantics) carry that revision. Both filament-contract-ir lock
  entries (ir, model) carry af45a9836e5963398fae414622e4def25faf7043. Cargo.lock holds no second
  revision of either repository. FSL's own Cargo.lock at 8f71444d pins filament-contract-ir to
  af45a983, so the IR pin matches FSL's and does not split the crate graph.
- Lock drift. The only other lock change is tempfile 3.27.0 now resolving getrandom 0.4.3
  instead of 0.3.4. tempfile declares a getrandom range covering both, both versions already
  sit in the lock, and tempfile is test-only here, so the change is harmless.
- `certificate: None`. At 8f71444d, fsl-replay/src/request.rs:462-464 documents the member as
  "the validated-witness certificate accompanying a hybrid replay (FSpec FR-652); a request of
  another source refuses it at /replay/certificate". Every codegen request source is
  `ReplaySource::Input` or `ReplaySource::Witness` (src/replay/function.rs:897, 1124;
  scalar_builder.rs:231; state_clause.rs:752; state_clause/graph.rs:588;
  state_clause/invariant.rs:434; frame.rs:845). None is hybrid, so `None` is the only value FSL
  accepts for them. Codegen never builds a hybrid source (it handles ReplayResult::Hybrid only
  as WrongArm / CgDefect).
- `same_wire`. FSL defines no PartialEq for ReplayRequestWire, so `same_wire` is the only
  comparison. It still destructures all 16 members exhaustively and compares each one, the
  new `certificate` included, so a future upstream member still fails to compile.
- Rust idiom: the changes add one field each. They introduce no new API, no unwrap, no
  allocation and no unsafe code.

Focused check: `cargo test --locked -p filament-contract-codegen --all-targets --no-run`, then
the replay unit tests; results in the Verdict.

## Verdict

Clean. The pins are consistent, with one revision per repository. The `certificate: None`
defaults match FSL's contract for non-hybrid sources, and the wire equality still compares
every member. Test oracle strength: the four touched sites only add a field to existing
fixtures and builders, so no assertion was weakened.
`scalar_actual_sent_context_and_every_driver_tie_are_independently_checked`
(tests/it/scalar_replay_binding.rs:343) still asserts that a changed target or changed bytes
is refused. No test changes `certificate` alone. A dropped comparison would still be caught at
compile time: the destructured binding would go unused, and `make lint` runs with
`-D warnings`. A new test would add little, so this is not raised as a finding.

Focused check results at 5f835865, run through locked-build.sh with debug=0 and -j4:
`cargo test --locked --all-targets --no-run` compiled lib, cg_gates and tests/it (exit 0);
`--lib replay::` 42 passed; `--test it -- composite_parity_converter scalar_replay_binding`
21 passed. The kani_obligations_symbolic_domains fixture compiles. Its tests need an
installed Kani and were not run.
