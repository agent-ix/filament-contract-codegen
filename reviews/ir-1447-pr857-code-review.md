## Summary

Ticket: IR-1447. The PR adds the closed collection predicate `IntegerIfAtMost`
`(if element < split then A else B) <= bound` (each branch the element or an integer literal,
`CollectionIfBranch`). `resolve_predicate` takes the `if` path only for an Integer element domain
with operation `filament.op.integer.le` and a `filament.op.control.if` left operand. The
condition must be `filament.op.integer.lt(element, literal)`, and the operands are read as
`[condition, then, else]`. The PR renders the predicate in the direct collection harness
(`spec.rs`) and in the whole-object operation harness (`render/collection_operation.rs`).

Checked by reading and by probes in the reviewer's worktree (FSL-compiled clauses, nothing hand
built):

- Soundness of the direct harness. The rendered `(if item < 2 { item } else { 2 }) <= 2` is an
  `i64` comparison on drawn elements with no arithmetic, so it is exact. The render sits inside
  the `(0..len).all/any` closure, which iterates the elements.
- Closed shape. Each of these FSL-emitted shapes is refused with `CollectionClaimNotRendered` /
  `UnsupportedClaimShape` and emits no harness: condition `<=`, condition `>`, `literal < item`,
  a condition with no element, branch `item + 1`, nested `if`, comparison `>=`, comparison `<`,
  non-literal bound `<= item`, `if` as the right operand (`2 >= if`, `0 <= if`), a Boolean
  element, and negative split, branch or bound (FSL emits a negation, not a literal). A literal
  beyond i64 is refused by FSL/IR. `= 2` is refused at IR admission. These shapes are accepted
  and their identities are correct: swapped literal/element branches (then=Literal 2,
  else=Element), both literal, both element, and `exists` (rendered with `.any`).
- Reader mapping. The operation identities are matched exactly (`integer.lt`, `integer.le`,
  `control.if`). The then/else order is pinned by the FSL fixture (then=Element, else=Literal 2;
  the mutant renders `else { 3 }`). Mutation M5 (swap the then/else destructuring) is killed.
- Identity. `IntegerIfAtMost` serializes under the unique serde tag `integer_if_at_most`, and
  `CollectionIfBranch` under the tag `branch`. Both feed the collection symbol digest material
  and `CollectionObligationIdentity`. Every match on `CollectionPredicateIdentity` is exhaustive
  with no wildcard (`spec.rs`, `render/collection_operation.rs`), so the compiler enforces the
  new arm. The healthy and mutant identities differ (asserted).
- Verdict binding. The runner refused a harness whose `rust.contents` was edited after
  generation ("the generated source or identity ... changed after generation"), so a verdict
  binds to the generated bytes.

## Verdict

The direct collection lowering is sound and closed as read and probed. Every out-of-shape `if`
tried is refused with the typed existing code. Nothing silently renders a different claim. The
reader maps FSL's IR exactly, and the identity change is complete. The 4 new tests kill each
mutation tried: M1 render `<` to `<=`, M2 render branch swap, M3 drop the `if` arm, M4 accept a
`<=` condition, M5 reader then/else swap and M6 accept `>=` comparison. M2 also fails the
installed healthy Kani test. Trace tags are `#[trace("FR-015-AC-155", "TC-025")]` and
`#[trace("FR-015-AC-159", "FR-017-AC-63", "TC-025")]`. The 2 Kani tests are `#[ignore]` and are
selected by `make kani-gate` (`KANI_FILTERS` includes `kani_obligations_symbolic_domains`).

Executed verdicts re-run by the reviewer, CG runner, installed Kani, each in its own
`systemd-run --user --scope -p MemoryMax=24G -p MemorySwapMax=0` under `flock`:

- healthy `Verified`: cover `Satisfied`, unwind checks success, test run 4.37 s cold, scope
  peak 1,116,151,808 B;
- mutant (source clause, else `3`) `Falsified`: the failing check is the harness assertion at
  `src/lib.rs:26` ("the symbolic collection satisfies the selected FSL forall body"), cover
  satisfied, test run 0.93 s, peak 188,338,176 B;
- bound mutant `<= 1`: `Falsified` with the collection `[2]`;
- loop probe: the else-3 mutant with the claim iteration set to `0..0` (raw `cargo kani`,
  hand-edited probe only) is `Verified`, so the falsification depends on iterating the drawn
  elements and the healthy proof is not vacuous.
